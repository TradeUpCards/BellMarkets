# Vercel Deployment Guide — BellMarkets Frontend

The `apps/web/` Next.js app deploys to Vercel from the monorepo root. The
`vercel.json` at the repo root tells Vercel how to handle the pnpm workspace.

---

## One-time setup

### 1. Connect the repo to Vercel

In the Vercel dashboard:
1. **New Project** → Import from Git
2. Select the BellMarkets GitHub repo (`TradeUpCards/BellMarkets`)
3. **Framework Preset:** Next.js (auto-detected from `apps/web`)
4. **Root Directory:** leave as `.` (root) — `vercel.json` handles the
   monorepo routing
5. **Build Command:** leave default (vercel.json overrides with
   `pnpm --filter @bell-markets/web build`)
6. **Output Directory:** leave default (vercel.json sets `apps/web/.next`)
7. **Install Command:** leave default (vercel.json sets
   `pnpm install --frozen-lockfile`)

### 2. Set environment variables

In Vercel project settings → Environment Variables, add the following.
Mark each as Production / Preview / Development as appropriate.

#### Required for trading (devnet demo)

```
NEXT_PUBLIC_BELL_MARKETS_PROGRAM_ID=599h7VznYR4CxyrG5nQbhR13qtRuwPcbnNr5QqbkS7uV
NEXT_PUBLIC_SOLANA_RPC=https://api.devnet.solana.com
```

If you have a Helius / QuickNode / Triton devnet RPC, use that instead of
the public endpoint (better rate limits + WebSocket reliability).

#### Required for /api/auth/* (OAuth login)

OAuth routes work without these but log-in flows will fail. Demo deploys
can omit; only the wallet-connect path is load-bearing.

```
NEXTAUTH_URL=https://<your-deployment>.vercel.app
NEXTAUTH_SECRET=<generate via: openssl rand -base64 32>

DISCORD_CLIENT_ID=
DISCORD_CLIENT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
TWITTER_CLIENT_ID=
TWITTER_CLIENT_SECRET=
```

Note: configure each OAuth provider's "Authorized Redirect URI" to:
`https://<your-deployment>.vercel.app/api/auth/callback/<provider>`

#### Required for /api/briefings/[ticker] (AI briefings)

```
DATABASE_URL=postgres://...   # Neon Postgres URL
```

The briefings themselves are pre-generated by `services/automation`
(Anthropic API). Vercel just READS from Neon — no Anthropic API key needed
on the frontend.

#### Optional — Helio subscriptions (Bell Pro tier)

```
HELIO_API_BASE_URL=https://api.hel.io
HELIO_API_KEY=
HELIO_PAYMENT_LINK_ID=
HELIO_WEBHOOK_SECRET=
```

Demo can omit; Bell Pro card renders without active payment flow.

### 3. First deploy

After saving env vars: **Deploy** from the Vercel dashboard, or push a
commit to the branch you configured Vercel to track (usually `main`).

Build should complete in ~3-5 min. Watch logs for:
- `pnpm install` finishing cleanly (frozen-lockfile must match)
- `next build` finishing without errors
- Static page generation completing for `/`, `/markets`, `/portfolio`, `/history`

---

## Ongoing deployments

- Every push to `main` triggers a production deploy
- Every PR triggers a preview deploy at a unique URL
- The `ignoreCommand` in `vercel.json` skips redundant builds when only
  files outside `apps/web/`, `services/automation/`, or the program IDL
  change (e.g. documentation-only commits don't rebuild)

---

## Smoke test after deploy

Once the production deploy lands:

1. **Open the deployed URL** — should redirect to `/` (landing)
2. **Connect wallet** (Phantom on devnet) — wallet button works
3. **Click into a trade page** (e.g. `/trade/META/610`) — order book renders
4. **Verify env vars are inlined**: open browser DevTools → Sources → search
   for the program ID `599h7VznYR4CxyrG5nQbhR13qtRuwPcbnNr5QqbkS7uV` in the
   JS bundles. If found, the public env var was inlined at build time. If
   not, the env var wasn't set in Vercel — fix + redeploy.
5. **Test a trade** — Buy YES Market on META @ 610 against the seeded book.

## Common deployment issues

| Symptom | Likely cause | Fix |
|---|---|---|
| Build fails at `pnpm install` | lockfile mismatch | Run `pnpm install` locally, commit `pnpm-lock.yaml`, redeploy |
| Build hangs at "Compiling" | Phoenix SDK CJS/ESM resolution (Windows-specific in dev; rare on Vercel) | If it happens, ensure `transpilePackages` in `next.config.mjs` includes `@ellipsis-labs/phoenix-sdk` |
| Runtime: "Module not found: bell-markets IDL" | `apps/web/src/idl/bell_markets.json` not committed | Verify the IDL file is committed; check `apps/web/.gitignore` doesn't exclude it |
| Runtime: 500 on `/api/briefings/AAPL` | `DATABASE_URL` not set or wrong | Check Vercel env var; verify Neon connection string |
| Trade page: "Connect wallet" never resolves | Wallet adapter SSR issue | Should be handled by existing wallet provider; check console for hydration errors |
| Trade page: "Program account not found" | Wrong RPC OR wrong program ID | Verify `NEXT_PUBLIC_SOLANA_RPC` points at devnet (not mainnet) and program ID matches deploy_index=8 |

## Production hardening (post-v1)

For a real production deploy beyond the demo:

1. **Custom domain** — `bellmarkets.com` or similar; configure in Vercel
   project settings
2. **Helius RPC** (or similar) — public devnet RPC will throttle under load
3. **Rate limiting** on API routes — `/api/auth/*`, `/api/briefings/*` should
   have rate limits (Vercel Edge Middleware or Upstash Redis-backed limiter)
4. **Analytics** — Vercel Analytics + custom event tracking
5. **Sentry / error tracking** — wallet errors, tx failures, OAuth callback issues
6. **Mainnet deployment** of the BellMarkets program — see
   `docs/architecture/pre-mainnet-readiness.md` for the readiness gate
7. **Replace bUSDC with Circle USDC** — for mainnet, `update_usdc_mint` to
   `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` (Circle USDC mainnet)
