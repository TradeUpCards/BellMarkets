How I built it: a directed multi-agent Claude Code workflow

I architected and shipped BellMarkets as a single human director (Tate role) orchestrating four named Claude Code lead agents — each owning a workstream with explicit file boundaries. The leads ran in separate WSL terminal sessions, each in its own git worktree (BellMarkets-aria, -bram, -cleo, -drew); I supervised in my main session as Tate. Every commit was reviewed by me before merge. This is the workflow this project was built with — and it's the workflow I'd use again.

Aria · Onchain

Rust / Anchor. The program at 599h7Vzn…. 27 instructions, 7 account types, 57 error variants. Owns the in-program CLOB matcher, settle/redeem invariants, vendored Pyth parser.

Bram · Automation

Node / TypeScript on Trigger.dev. Morning create-markets, post-close grid evolution, settlement nudger. AI briefings (Claude Sonnet). Neon Postgres for product state.

Cleo · Frontend

Next.js 14 / React 18 / TypeScript / Tailwind. Wallet adapter (Phantom/Backpack/Solflare). v8 trading-terminal design. Live order book, four atomic trade flows, Helius proxy.

Drew · Quality

Invariant tests, chain-simulate integration tests, pre-mainnet-readiness narrative, demo runbook, Sonnet defense-in-depth audits.

The leads aren't humans I delegated to — they're Claude Code sessions I directed in parallel. The output (27 ixs of Rust, ~3K lines of TypeScript across automation and frontend, 100+ invariant tests, 8 on-chain deploys) is mine to defend. The workflow is what made it possible in five days.

Day 4 — Sun 2026-05-24 evening: THE PIVOT

DR-020 PIVOT   Phoenix → in-program CLOB

What went wrong: Phoenix integration on devnet hit a chicken-and-egg bootstrap problem we could not solve inside the build window. Phoenix's InitializeMarket requires the YES base mint to exist at the time it's called — but our program creates the YES mint as part of create_strike_market. The bootstrap order is unworkable without a multi-step admin orchestration we didn't have time to implement and audit.

What I did: Adopted Keith Mazanec's parallel-cohort in-program CLOB reference design with adversarial review pre-applied. Wholesale, not invented from scratch. 5 new ixs (init_order_book, grow_order_book, place_order, cancel_order, match_orders) + new OrderBook zero-copy account (16,448 B per market) + 2 escrow PDAs per strike. Phoenix code stays dormant in the program (additive, not removed) for Phoenix-as-secondary-venue v2 candidate.

The senior-engineer move: The interview defense isn't "I built it from scratch." It's "I recognized when not to NIH. Adopting a peer's design with their adversarial review baked in is shorter audit surface, faster review, fewer novel bugs." Documented in docs/architecture/reference-clob-{design,decisions,spec}.md.

  • DR-016 Token program selection (SPL for tradeable, Token-2022 for platform NFTs, compressed for badges)
  • DR-017 Vault security model — PDA self-authority + finite list of vault destinations
  • DR-018 Fee model v1.5 (amendment of DR-008)
  • DR-019 NO is market-only in v1 (Limit NO would strand fees on cancel)
  • DR-020 The pivot itself — supersedes DR-001, defers DR-009

The retrospective

What I'd do differently

  • Test Phoenix devnet bootstrap on Day 1, not Day 4. The whole DR-020 pivot would have been a 30-minute investigation on Day 1 instead of an emergency push on Day 4. I assumed integration would work because the SDK existed.
  • Add mint::close_authority to mints at Day 1. Would unlock v1.2 mint-close rent recovery without a future program upgrade. ~$2K/year stranded that I could've prevented for one line of code.
  • Lock the IDL placement pattern across services on Day 1. Tonight's seed-script ran into IDL-not-found and IDL-placeholder issues that cost ~30 min of debugging. A single source of truth for the IDL (one file, symlinks elsewhere) would have prevented this.
  • Cost-shifting (DR-005 Meteora pattern) should have been a Day 0 decision. I had the platform-funded design baked in until Day 2, then refactored. The Day-0 brainlift should have asked "who pays for PDA rent at scale?" — it didn't.
  • Start the demo runbook on Day 1. Drew's docs/demo/test-runbook.html didn't exist until late. Writing it earlier would have caught UX gaps while there was time to fix them properly instead of patching at the end.

What worked

  • The multi-agent Claude Code workflow. Five days, four parallel workstreams, ~3000 lines of TypeScript + 27 Anchor instructions + 100+ tests + an entire frontend. Single director (me); no human teammates.
  • The constitution/decisions.md discipline. 20 DRs locked, each with trade-off line. When DR-020 happened, the diff was clean — the superseded DR-001 stays visible, the new DR-020 references it. No silent rewrite of history.
  • The brainlift + SDD scaffolding. Every Claude Code session re-read the constitution before writing code. Drift was minimal compared to a code-first workflow.
  • Sonnet adversarial audits after each major push. Caught ~17 substantive findings across 7 cycles. Bias-diversification (different model than the writer) is real and underused.
  • The pivot itself. 30 hours before submission, I rebuilt the matching layer of the protocol. The submission still ships an E2E trade verified on-chain. That's a workflow story worth telling.
