BellMarkets — System Design

Architecture · decisions · trade-offs · risks · lessons · technical challenges

Cory Vandenberg · GauntletAI "Meridian" · Submission 2026-05-25 · Program: 599h7VznYR4CxyrG5nQbhR13qtRuwPcbnNr5QqbkS7uV (Solana devnet, deploy_index=9)

1. What we built (in one paragraph)

BellMarkets is a non-custodial Solana dApp for binary outcome contracts on daily MAG7 stock closes. Each contract asks "Will [STOCK] close above [PRICE] today?" — two SPL tokens per contract (YES + NO) trade against bUSDC on an in-program order book that lives inside the Anchor program. At 4:00 PM ET, the program reads Pyth's MAG7 equity feed; winners redeem $1 bUSDC per winning token. YES payout + NO payout = $1.00 exactly — the load-bearing invariant. Three runtime surfaces: an Anchor program (the authority + matcher), a Trigger.dev automation service (orchestration only, no signing authority), and a Next.js trading terminal at bell-markets.vercel.app. 28 instructions, 7 account types, 57 error variants, 9 deploys, 6.683 SOL spent. Full lifecycle (create → mint → trade → settle → redeem) verified on-chain on submission day.

4. Trade-offs accepted (with eyes open)

Phoenix dependency → no fallback CLOB

DR-020 puts the matcher in our program. If a bug surfaces post-mainnet, there is no alternative venue — admin pause is the circuit breaker. Pre-mainnet audit is the load-bearing gate.

Pyth dependency → no fallback oracle

DR-003 commits to Pyth. If Pyth has an outage at 4pm ET, settlement waits on the 1-hour time-delayed admin_settle. We deliberately rejected Switchboard as a fallback — doubles integration surface for a vanishingly rare failure mode. Pyth confidence + staleness gates are tight enough that we'd rather block than settle on bad data.

OrderBook capacity capped at 128 orders/side per market

Adequate for demo + early mainnet; not a deep-liquidity venue. Each market's OrderBook is 16,448 B (the largest single per-market cost). Expansion to 256 or slab-style is a v2 schema change requiring migration planning.

Limit NO disabled (DR-019)

NO-side trades are market-only in v1 because a resting Limit NO would strand fees on cancel (the atomic Buy NO = mint_pair + place_order(SELL_YES, IOC); a Limit NO would have to escrow YES tokens that don't exist yet). Limit YES + 4 atomic flows remain. Limit NO returns when the fee model handles the inverse.

v1.1 rent recovery deferred to post-submission

OrderBook PDAs hold ~0.115 SOL of rent each — at scale that's ~187 SOL/month leaking. close_settled_market recovers only the vault (~$0.32/market on mainnet). The full design (force_cancel_order + close_order_book) is documented in specs/deferred.md + docs/architecture/pre-mainnet-readiness.md §"v2 gap #8" as a hard pre-mainnet precondition. Not blocking for submission; blocking for production.

SPL Token (legacy), not Token-2022 (DR-016)

YES/NO/USDC use SPL Token, not Token-2022. Vault arithmetic depends on no transfer-fee skew; Phoenix v1 (when integration was the plan) required it; audit surface stays minimal. Token-2022 is planned for v2 platform NFTs (Founder Pass per DR-013) and v2 compressed badges — ~$50/year extra rent at 10K MAU for tradeable accounts is acceptable.

5. Risks (mainnet-conversation gates)

P0   No formal third-party audit of the in-program matcher

The matcher is novel audit surface (DR-020). Sonnet defense-in-depth audits caught the obvious classes (H-1 maker-account verification, M-2 PDA seed constraint, M-4 zero-price reject) and 138/138 Rust property tests pass. None of that substitutes for a formal audit. Pre-mainnet: third-party audit is non-negotiable.

P0   OrderBook + escrow rent stranded at scale

~0.122 SOL/market not recoverable today. At 1,470 markets/month (49/day × 30 days), that's ~187 SOL/month = ~$30K/month at $160 SOL. Economically unsustainable for mainnet. v1.1 design recovers 95.2% — must ship before any mainnet deploy.

P1   Pyth devnet feed staleness (audited)

Audit landed on submission day (docs/pyth-feed-status.md). Headline: Pyth v2 push feeds on devnet last published ~660 days ago (SOL/USD agg_pub_slot=322,338,250 vs current=464,963,388 → 142M slots delta). settle_market reverts PythStale (6009) on devnet for every tested feed. All MAG7 equity pubkeys probed: AccountNotFound (Pyth devnet is crypto-only). Operational settle path on devnet is admin_settle only — proven on-chain (tx 5BFRyVW1…fXepU). Hermes HTTP equity feeds DO publish MAG7 prices (network-agnostic) and power the off-chain briefings pipeline. v1.5 fix: Pyth Pull migration — same code path on mainnet uses live feeds with no admin fallback.

P1   force_redeem doesn't cover Invalid markets (DR-005 v2 gap)

If a market settles Invalid (e.g., Pyth-unrecoverable + admin override didn't fire), force_redeem can't unstick winning positions because it gates on Yes/No outcome. v2 plan: add an force_redeem_invalid path that fires on Invalid + grace.

P2   No mainnet keypair architecture

Hard NO #1 keeps mainnet keypairs out of the cohort-build stage. Pre-mainnet: replicate the w3Swap separation-of-authority pattern — program ID + upgrade authority + platform admin + fee collector keypairs, each with operational signing procedures.

6. Technical challenges (and how each was solved)

Phoenix bootstrap dependency loop

Problem: Phoenix's InitializeMarket requires the YES base mint to exist at call time. Our program creates the YES mint inside create_strike_market. Bootstrap order: chicken-and-egg.

Solution: DR-020 PIVOT   Built the matcher in-program. Adopted Keith Mazanec's parallel-cohort reference design with adversarial review pre-applied. Wholesale, not invented. 5 new ixs + zero-copy OrderBook + 2 escrow PDAs per strike. 30 hours before submission.

BPF stack overflow on heavy Anchor accounts

Problem: Anchor's try_accounts deserializes Account<T> fields onto the BPF stack (4 KB per frame). Three or more unboxed heavy accounts (Mint, TokenAccount, MarketConfig, StrikeMarket, UserPosition) silently overflow — program compiles, deploys, fails at runtime with cryptic errors. Source: LESSONS.md Lesson 9.

Solution: hard-rules.md §4.10 — Box<Account<'info, T>> on every heavy account by default. Drew flags any PR that unboxes during review. CI greps for "Stack offset exceeded" warnings and fails the pipeline (§4.11) — the warning IS the failure mode, just disguised.

OrderBook size vs Solana's MAX_PERMITTED_DATA_INCREASE

Problem: OrderBook::LEN = 16,448 B. Solana caps a single realloc at 10 KB. init_if_needed can't create the account at 16 KB in one shot.

Solution: Two-phase init. init_order_book allocates 10 KB; grow_order_book reallocs to OrderBook::LEN and writes the bump byte + sets strike_market.order_book (the trading gate). Both ixs are permissionless. place_order won't fire until the trading gate is open.

Pyth SDK Borsh-version cascade

Problem: pyth-sdk-solana pins a Borsh version incompatible with Anchor 0.31. Importing it breaks the build with a cascade of version conflicts. Documented in LESSONS.md Lesson 1 by a same-project veteran.

Solution: Vendored a 30-line Pyth price-account parser at programs/bell-markets/src/oracle.rs. Validates magic number, reads price/confidence/exponent/publish_slot at known byte offsets, returns a typed PriceData struct. Pyth's binary layout is documented and stable. hard-rules.md §4.13 enforces: do not add pyth-sdk-solana to Cargo.toml.

bUSDC mint migration with stranded reward pools

Problem: After update_usdc_mint flipped config.usdc_mint from Circle devnet USDC to our self-controlled bUSDC, existing weekly/monthly reward-pool token accounts were bound to the old mint. mint_pair's fee-routing CPI hit a has_one mismatch.

Solution: Path B chosen over Path A (revert to Circle USDC). Added reinit_rewards_pools admin ix at deploy_index=8 — closes + re-initializes the 2 pool PDAs at the same addresses bound to the new mint. Manual 3-step CPI dance (close_account → create_account → initialize_account3) because Anchor's init + close don't compose on the same PDA in a single tx. Pre-flight checks: account owner == SPL Token, data.len() >= 165, amount == 0, self-authority.

Helius API key client-side exposure risk

Problem: Initial wiring exposed the Helius RPC URL via NEXT_PUBLIC_SOLANA_RPC — leaked credential, visible to anyone inspecting the browser bundle.

Solution: Server-side proxy route at apps/web/app/api/solana-rpc/route.ts. Key stays in Vercel server env (HELIUS_API_KEY_DEVNET). Frontend resolves /api/solana-rpc?network=devnet against window.location.origin in the browser; falls back to clusterApiUrl(devnet) during SSR/SSG. Hard NO #13 codifies: Helius key NEVER appears in NEXT_PUBLIC_*.

8. Lessons learned

Test the SDK's preconditions on Day 1, not Day 4

Phoenix bootstrap could have been a 30-minute investigation on Day 1. Assuming the SDK works because it exists is the most expensive shortcut I took.

Adopting a peer's adversarially-reviewed design > inventing from scratch

The DR-020 pivot wasn't "build a matcher" — it was "find a vetted matcher and adopt it." Keith Mazanec's parallel-cohort reference design came with Sonnet adversarial review pre-applied. Shorter audit surface. Faster review. Fewer novel bugs. The interview defense is the senior-engineer move.

The chain is canonical for funds; the DB serves product surface

The Day-0 brainlift said "no DB at all" — a stronger non-custodial narrative but unrealistic for AI briefings + OAuth + leaderboard reads. DR-003 was amended to split the responsibility: funds stay on chain (DB can be wiped without affecting redemption), product features live in Neon. Mainnet-ready posture without the maximalist over-claim.

Permissionless cranks > authority bottlenecks

DR-002 (permissionless settle) generalized post-DR-020 into a pattern: match_orders is permissionless, close_settled_market is permissionless, the v1.1 force_cancel_order + close_order_book will be permissionless. The cron is convenience; users can crank. The system survives operator failure by design, not by retry policy.

Zero-copy is mandatory for large Anchor accounts

The OrderBook is 16 KB. Anchor's regular Account<T> would deserialize it onto the BPF stack and overflow silently. Pattern: #[account(zero_copy)] + AccountLoader<'info, OrderBook> + load_mut() / load(). Never hold a load() across a CPI boundary.

Multi-agent orchestration needs clean file ownership

constitution/file-ownership.md declared who owns what before any code was written. Aria owns programs/**; Bram owns services/automation/**; Cleo owns apps/web/**; Drew owns tests/** + audit reports. Cross-workstream PRs required both leads' sign-off. Five days, four parallel workstreams, zero serious merge conflicts.

9. What I'd do differently

  • Test Phoenix devnet bootstrap on Day 1 — would have saved Day-4 pivot trauma.
  • Add mint::close_authority to mints on Day 1 — would unlock v1.2 mint-close rent recovery without a future program upgrade.
  • Cost-shifting decision (DR-005 Meteora pattern) should be Day 0 — I had platform-funded design baked in until Day 2, then refactored. Day-0 brainlift didn't ask "who pays for PDA rent at scale?".
  • Start the demo runbook on Day 1 — Drew's runbook didn't exist until late. Earlier writing catches UX gaps when there's time to fix them.
  • Lock the IDL placement pattern across services on Day 1 — tonight's seed-script blocked on IDL placeholder issues. One source of truth + symlinks would have prevented it.
  • Build a smaller initial program binary — Deploy 5 jumped 312 KB and required a 2-SOL top-up. Slicing the leaderboard/distribution work into a separate program (or behind feature flags) would have kept upgrade costs trivial.

10. Next steps (post-submission)

v1.1 (P1 pre-mainnet preconditions)

  • force_cancel_order(side, seq) — permissionless, post-settle only. Sweeps stale orders. Refunds maker escrow to maker's ATA (verified for ownership + mint via the same verify_maker_account pattern place_order already uses).
  • close_order_book() — permissionless. Gated on bids_len + asks_len + escrow balances == 0. Closes OrderBook + both escrows. Clears strike_market.order_book = Pubkey::default() on close (self-consistent post-close state). Recovers ~0.121 SOL per market = 95.2% of per-market rent.
  • Real Pyth MAG7 feed audit per ticker (Drew → docs/pyth-feed-status.md).
  • Formal third-party audit of the in-program matcher (highest-risk new surface).
  • Mainnet keypair architecture (DR-016 v2 plan: program ID + upgrade authority + platform admin + fee collector keypairs).

v1.2 (post-mainnet polish)

  • close_market_mints() — recovers the remaining 4.8% stranded rent (mints). Requires mint::close_authority = strike_market on the Anchor init schema in create_strike_market — a program upgrade. Defer until the next program upgrade fires for an unrelated reason; ride along.
  • Phoenix-as-secondary-venue integration (DR-009 Model D) — Phoenix CPI code is still dormant in the program for this v2 candidate.
  • OrderBook capacity expansion (256 or slab-style) — schema change requiring migration planning.
  • Token-2022 platform NFTs (DR-013 Founder Pass) + compressed badges (Bubblegum, ~1000× cheaper rent than SPL).
